# W1 NFC Reader v2.1 — historical real-time / UTC timeline proposal

Status: **SUPERSEDED**

This document is retained only as a historical design record. It must not be used as the current v2.1 product contract.

The original proposal exposed two peer product modes (`LOCAL` and `METER`). Real-device evidence and later product decisions replaced that model with one canonical reconstructed real-time timeline.

## Current authoritative decision

Use:

- `docs/product-decisions/v2.1-canonical-real-time-product-timeline.md`
- `docs/V2_1_TIME_MODEL_IMPLEMENTATION.md`
- `docs/V2_1_CANONICAL_REAL_TIME_VALIDATION_ADDENDUM.md`

The current v2.1 rules are:

- normal product UI exposes one canonical real timeline;
- Live primary time is the actual Android acquisition epoch;
- archive primary time is reconstructed from the **single newest fully verified Live/default anchor for that physical meter** plus native monotonic `ON_TIME`;
- the reconstructed UTC timeline is projected through the persisted per-meter IANA timezone for civil/local display;
- raw meter/logger wall-clock remains preserved secondary evidence and is never silently promoted to canonical time;
- the former global `LOCAL / METER` selector is not a normal product feature;
- old/restored development state that contains `METER` is normalized to the canonical path;
- one active anchor is used for the complete stored timeline of a meter, so native interval durations cannot be stretched or compressed by anchor handover;
- an archive `ON_TIME` newer than the active anchor fails closed;
- a backwards/reset `ON_TIME` requires explicit reset/generation handling rather than guessing;
- Home Assistant deduplication must use deterministic meter-native `source_record_id`, never reconstructed UTC or phone-local state;
- Android will not maintain an authoritative "already sent" ledger for Home Assistant.

## Historical note

The superseded proposal was useful during exploration of timezone assignment, DST handling, partial-edge statistics coverage and raw meter-clock evidence. Those parts that remained valid were carried forward into the canonical decision and implementation documents above.

Do not reintroduce the peer `METER` product mode from this historical document without a new explicit product decision and new physical validation.
